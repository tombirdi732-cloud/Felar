# FELAR

Хоррор от первого лица на Unreal Engine 5 в эстетике found footage: игрок смотрит на мир
через видоискатель старого камкордера. Весь геймплей — на C++, классы спроектированы так,
чтобы от них наследовались Blueprint'ы: настройка, меши, звук и UI собираются в редакторе.

---

## Идея

**Свет одновременно спасает и убивает.**

Три системы давят друг на друга и не дают ни одной безопасной стратегии:

| Система | Что требует |
|---|---|
| **Фонарь** | Без него ничего не найти. Но существо видит свет с 3000 единиц вместо 450. Батарея садится за ~2 минуты. |
| **Страх** | В темноте растёт. Выше 70% игрок непроизвольно ахает — это шум. На 100% происходит срыв: крик слышно на всю карту. |
| **Существо** | Патрулирует, идёт на шум, гонится по прямой видимости, обыскивает район, где потеряло игрока. |

Отсюда центральная дилемма: выключить фонарь безопасно от существа, но страх загонит
тебя в срыв. Держать фонарь включённым — тебя увидят. Играть приходится короткими
перебежками со светом и паузами в темноте, ровно до того момента, пока хватает нервов.

**Цель:** собрать все фрагменты, разбросанные по уровню, и открыть выход.

## Что нужно, чтобы это запустить

Важно понимать: **это не мод и не плагин**, который «загружается в игру». Это исходный
код игры. Его нужно **скомпилировать**, и результатом будет сама игра.

Что должно быть установлено:

1. **Unreal Engine 5.8** (проект помечен под неё; на 5.4–5.7 редактор предложит
   сконвертировать и обычно собирается без правок).
   Ставится через Epic Games Launcher, вкладка Unreal Engine → Library.
2. **Компилятор C++**:
   - **Windows:** Visual Studio 2022 Community (бесплатна). При установке обязательно
     отметь галочку **«Разработка игр на C++»** (Game development with C++).
     Без неё Unreal не сможет собрать проект.
   - **Linux:** clang идёт в комплекте с движком.
   - **macOS:** Xcode из App Store.

Порядок действий:

1. Распакуй архив в папку без кириллицы и пробелов в пути.
   Хорошо: `D:\Games\Felar`. Плохо: `C:\Мои проекты\хоррор игра`.
2. Правый клик по `Felar.uproject` → **Generate Visual Studio project files**.
   (На Linux/macOS — соответствующий скрипт генерации из папки движка.)
3. Открой появившийся `Felar.sln`, выбери конфигурацию **Development Editor**,
   собери (`Build → Build Solution`). Первая сборка идёт 5–20 минут.
4. Открой `Felar.uproject` — запустится редактор Unreal.

Можно и проще: просто дважды кликнуть `Felar.uproject`. Редактор увидит несобранный
модуль и предложит скомпилировать сам. Но если сборка упадёт, ошибку будет видно
хуже, чем в Visual Studio.

> **Уровня (`.umap`) в архиве нет** — это бинарный ассет Unreal, его нельзя сохранить
> как текстовый файл. Уровень придётся построить самому, это минут двадцать.
> Без него игра запустится в пустоту.
>
> **А вот Blueprint'ы делать не нужно.** Все объекты уже носят встроенные модели
> движка и работают сразу после компиляции — их можно тащить на карту напрямую.
> Blueprint'ы понадобятся только когда дойдёшь до своих моделей и звуков.

## Сборка уровня в редакторе

### 1. Карта

- **File → New Level → Basic**. Сохрани как `Content/Maps/L_House`.
- **Project Settings → Maps & Modes**: `Editor Startup Map` и `Game Default Map` → `L_House`.
- Построй коробку из BSP или кубов: несколько комнат, коридоры, двери. Точность неважна —
  важна планировка: тупики, петли и развилки. Прямой коридор без ответвлений убивает всю игру.
- **Удали с карты стандартные `DirectionalLight`, `SkyLight`, `SkyAtmosphere`, `ExponentialHeightFog`
  и `PostProcessVolume`**, которые ставит шаблон Basic. Их заменит один актор `BP_Night`
  (см. раздел «Ночь и туман»). Два комплекта освещения на карте будут драться друг с другом.

### 2. Навигация (без неё существо не сдвинется с места)

- Добавь **NavMeshBoundsVolume**, растяни на всю играбельную зону.
- Нажми `P` — зелёная заливка показывает, где существо может ходить. Если её нет,
  проверь, что пол — статичная геометрия, а объём накрывает уровень.

### 3. Расстановка объектов

**Blueprint'ы создавать не нужно.** У всех объектов уже подставлены встроенные модели
движка (`/Engine/BasicShapes`), поэтому C++ классы можно тащить на карту напрямую из
панели **Place Actors** — ищи их по названию. Они сразу видимые и рабочие.

Что расставить:

| Класс | Сколько | Куда |
|---|---|---|
| `NightAtmosphere` | 1 | Где угодно, положение не важно |
| `FragmentPickup` | 6 | По дальним углам карты |
| `BatteryPickup` | 3–4 | По маршруту между фрагментами |
| `HidingSpot` | 3–5 | Рядом с местами, где существо ходит часто |
| `SafeLightZone` | 2–3 | + настоящая лампа рядом с каждой |
| `ExitDoor` | 1 | У выхода |
| `StalkerCharacter` | 1 | Подальше от точки старта игрока |
| `PlayerStart` | 1 | Точка появления игрока |

Количество нужных фрагментов считается автоматически по числу расставленных — задавать
его вручную не надо.

**Точки патрулирования:** расставь пустых актёров (`Empty Actor`) по уровню и добавь
каждому тег `PatrolPoint` (Details → Actor → Tags). Если точек нет, существо будет
бродить случайно — работает, но маршрут получается менее осмысленным.

**Режим игры:** в **World Settings** выстави `GameMode Override` → `FelarGameMode`.

> **Важно про `HidingSpot`:** если заменишь заглушку на свою модель шкафа, проверь,
> что `ExitPoint` остался **снаружи** меша. Если он внутри, игрок при выходе окажется
> замурован в геометрии.

### 4. Blueprint'ы — потом, когда понадобятся

Для рабочей игры они не нужны. Но как только захочешь свои модели и звуки, делать это
на каждом экземпляре по отдельности станет мучительно. Тогда создай наследников
(**Content Browser → Add → Blueprint Class → All Classes**) и ставь на карту уже их:

| Родитель (C++) | Что в нём настраивать |
|---|---|
| `FragmentPickup` | Своя модель вместо сферы, звук подбора |
| `BatteryPickup` | Своя модель, `ChargeAmount` |
| `HidingSpot` | Меш шкафа, положение `HidePoint` и `ExitPoint` |
| `ExitDoor` | Меш двери, анимация в `OnDoorOpenedBP` |
| `StalkerCharacter` | Скелетный меш + Anim Blueprint, звуки в `OnStateChangedBP` |
| `NightAtmosphere` | Свои пресеты ночи под разные локации |
| `FelarPlayerController` | `HUDWidgetClass`, если добавишь UMG-меню |

Логику в них писать не нужно — она вся в C++. Blueprint здесь только держит модель,
звук и числа.

**У существа** заглушка лежит в отдельном компоненте `PlaceholderMesh`. Когда назначишь
скелетный меш на штатный компонент `Mesh`, заглушку просто скрой или удали — на логику
она не влияет.

### 5. Интерфейс

Экранная индикация камкордера — REC, таймкод, заряд, счётчик фрагментов, подсказки
взаимодействия — **уже работает и не требует ничего настраивать**. Она нарисована
через Canvas в `AVHSHud` и включается сама.

UMG нужен только для того, чего в этой индикации нет: меню, экрана смерти, титров.
Если он понадобится — создай Widget Blueprint и укажи его в `BP_PlayerController →
HUDWidgetClass`. Подписаться можно на любое из этих событий:

- `UFlashlightComponent::OnBatteryChanged`, `OnBatteryDepleted`
- `UFearComponent::OnFearChanged`, `OnPanicStateChanged`, `OnFearBreakdown`
- `UInteractionComponent::OnFocusedActorChanged`
- `AFelarGameState::OnFragmentsChanged`, `OnGameFinished`
- `AFelarCharacter::OnPlayerCaught`, `OnStaminaChanged`, `OnHidingStateChanged`

## Камера VHS

`UVHSCameraComponent` заменяет обычную камеру у игрока. Эффект собран из трёх слоёв:

**1. Пост-обработка.** Хроматические аберрации, виньетка, зерно, выцветшая
насыщенность, холодный оттенок плёнки, ручная экспозиция. Всё это штатные поля
`FPostProcessSettings`, поэтому не требует ни одного ассета.

**2. Дрожание рук.** Многослойный шум Перлина на поворот, смещение и наклон камеры.
Три оси берут шум из разных точек — без этого камера качалась бы строго по диагонали
и выглядела механически. На бегу тряска усиливается вдвое.

**3. Сбои плёнки.** Раз в 9–28 секунд кадр на четверть секунды «ведёт»: подскакивают
аберрации, картинку кренит. Плюс ручные срабатывания в ключевых моментах.

**Связь со страхом.** `FelarCharacter` каждый кадр отдаёт уровень страха в камеру.
Чем страшнее — тем сильнее и мельче дрожь и тем чаще срывается плёнка. Состояние
персонажа читается прямо с картинки, без единого элемента интерфейса. При срыве
страха и при смерти запускается длинный сбой записи.

### Чего здесь нет и почему

Настоящих развёрток, изгиба строк и «уползающего» кадра. Это делается **только
материалом пост-процесса**, а материал — бинарный ассет, я его в архив положить не мог.

Если захочешь добавить — вот рецепт. Создай **Material**, `Material Domain = Post Process`,
и собери в нём:

- **Изгиб строк:** `TextureCoordinate` → к `U` прибавить `sin(V * 400 + Time * 3) * 0.0015`
  → этим UV сэмплить `SceneTexture: PostProcessInput0`.
- **Полоса помех:** `frac(V - Time * 0.15)` → `smoothstep` узкой полосой → в этой полосе
  добавить к `U` ещё `0.02`.
- **Строки развёртки:** `sin(V * ScreenHeight * 3.14)` → умножить результат на `0.9..1.0`.
  (В `AVHSHud` они уже есть через Canvas, так что этот шаг опционален.)
- **Шум ленты:** `Time` в `Noise` → добавить к цвету с малым весом.

Готовый материал добавь в `PostProcessSettings → Post Process Materials` на
`BP_Player → Camera`. C++-часть эффекта продолжит работать поверх.

## Ночь и туман

`ANightAtmosphere` — одна кнопка «сделать ночь». Внутри четыре компонента, настроенных
согласованно: луна (`DirectionalLight`), рассеянный свет неба (`SkyLight`), небо
(`SkyAtmosphere`) и объёмный туман (`ExponentialHeightFog`).

Все параметры применяются **прямо в редакторе**, без запуска игры: плотность тумана
и угол луны подбираются только на глаз, и делать это через `Play` невыносимо медленно.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `MoonIntensity` | 0.35 лк | Яркость луны. Настоящее полнолуние ≈ 0.25. Выше 1.0 — уже пасмурный день |
| `MoonPitch` | −32° | Высота над горизонтом. Низкая луна = длинные тени |
| `MoonColor` | холодный синий | Так мозг ожидает увидеть лунный свет |
| `SkyLightIntensity` | 0.12 | Подсветка теней. Ноль — абсолютно чёрные тени, играть невозможно |
| `FogDensity` | 0.035 | Главный рычаг дальности видимости |
| `bVolumetricFog` | вкл | Свет фонаря становится видимым конусом в воздухе |
| `VolumetricFogDistance` | 8000 | Дальность просчёта объёма — самый дорогой параметр |

**Ради чего всё это:** с объёмным туманом луч фонаря виден в воздухе, а лунный свет
падает из окон настоящими лучами. Это половина атмосферы хоррора, и получается почти
бесплатно по трудозатратам.

**Если тормозит:** первым делом выключай `bVolumetricFog`, вторым — снижай
`VolumetricFogDistance`. Всё остальное здесь стоит копейки.

> **Автоэкспозиция отключена** в трёх местах: `DefaultEngine.ini`, `UVHSCameraComponent`
> и косвенно через настройки камеры. Это не перестраховка — с включённой автоэкспозицией
> движок сам «вытягивает» тёмные комнаты до нормальной яркости, и никакой темноты
> в игре не остаётся. Если однажды ночь вдруг станет светлой, ищи причину здесь.

### Почему сделано именно так

**Компоненты, а не один жирный класс персонажа.** Фонарь, страх и взаимодействие —
три независимых `ActorComponent`. Каждый можно тестировать, отключать и вешать на
другого актора отдельно. `FelarCharacter` только связывает их и переводит ввод в события.

**Интерфейс вместо Cast.** `IFelarInteractable` даёт игроку работать с дверью, шкафом и
запиской одинаково, без `Cast To BP_Door` на каждый тип. Каждый `Cast` в Blueprint тянет
весь целевой класс со всеми его ассетами в память при загрузке — на большом проекте это
превращается в минуты загрузки.

**Делегаты вместо прямых ссылок.** Компоненты не знают ни про UI, ни друг про друга:
они рассылают события, а подписчики сами решают, что с ними делать. Поэтому
`FearComponent` понятия не имеет о существовании существа — шум из его событий делает
`FelarCharacter`.

**Конечный автомат на C++ вместо Behavior Tree.** BT и Blackboard — бинарные ассеты:
их нельзя положить в архив как текст, нельзя нормально отревьюить и нельзя смержить,
если двое правили один файл. Для четырёх состояний автомат в коде короче и полностью читаем.

**Enhanced Input, собранный в коде.** Обычно Input Action и Mapping Context — это
бинарные ассеты, и проект, который от них зависит, не собрался бы из одних текстовых
файлов. Здесь они создаются прямо в конструкторе персонажа (`BuildInputMappings`),
поэтому управление работает сразу после компиляции. Там же меняется раскладка —
метод виртуальный, его можно переопределить в наследнике.

**Canvas-HUD вместо UMG.** По той же причине: индикация камкордера работает сразу после
сборки. Для меню и инвентаря UMG удобнее, а эта «наклейка поверх кадра» останется здесь.

**Дрожание камеры накладывается на вид, а не на трансформ компонента.** Иначе тряслась
бы и трассировка взаимодействия, и проверка видимости существа — прицелиться в предмет
в панике стало бы невозможно. Трясётся только картинка.

**Дозированный Tick.** Трассировка взаимодействия — раз в 0.1 с, проверка видимости
существа — раз в 0.25 с, перестроение пути в погоне — раз в 0.35 с, радиус зрения
пересчитывается только при смене состояния фонаря. Разницы в поведении не видно,
а нагрузка падает в разы. Фонарь и шкаф вообще тикают только когда работают.

## Настройка баланса

Все числа вынесены в `EditDefaultsOnly` — правятся в Blueprint'ах без перекомпиляции C++.

| Что | Где | По умолчанию |
|---|---|---|
| Время работы фонаря | `FlashlightComponent → DrainPerSecond` | 0.8 (~2 мин) |
| Скорость роста страха | `FearComponent → DarknessFearPerSecond` | 4.5 |
| Порог паники | `FearComponent → PanicThreshold` | 70 |
| Зрение в темноте | `StalkerCharacter → SightRadiusDark` | 450 |
| Зрение на свету | `StalkerCharacter → SightRadiusLit` | 3000 |
| Слух | `StalkerCharacter → HearingRange` | 2200 |
| Скорость погони | `StalkerCharacter → ChaseSpeed` | 560 |
| Сила дрожи камеры | `VHSCameraComponent → BaseSwayAngle` / `PanicSwayAngle` | 0.45 / 2.2 |
| Частота сбоев плёнки | `VHSCameraComponent → MinGlitchInterval` | 9 с |
| Плотность тумана | `NightAtmosphere → FogDensity` | 0.035 |

Скорость погони (560) намеренно ниже скорости бега игрока (600): от существа **можно**
убежать, но запаса хватает секунд на десять, пока не кончится выносливость.
Если сделать существо быстрее игрока, погоня превратится в гарантированную смерть,
и игрок перестанет рисковать вообще.

## Отладка

```
Log LogFelar Verbose      # подробный лог: состояния ИИ, шум, страх
ShowDebug AI              # состояние ИИ поверх экрана
show Navigation           # навмеш прямо в игре
stat unit                 # общая производительность
r.VolumetricFog 0         # выключить объёмный туман, если тормозит
```

Чтобы временно отключить VHS-эффект и посмотреть на «чистую» картинку —
вызови `SetVHSEnabled(false)` на камере игрока (доступно из Blueprint).

## Что дальше

Порядок, в котором стоит наращивать игру:
