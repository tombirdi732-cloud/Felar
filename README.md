# FELAR

Хоррор от первого лица на Unreal Engine 5. Весь геймплей — на C++, классы спроектированы
так, чтобы от них наследовались Blueprint'ы: настройка, меши, звук и UI собираются в редакторе.

---

## Идея

**Свет одновременно спасает и убивает.**

Три системы давят друг на друга и не дают ни одной безопасной стратегии:

| Система | Что требует |
|---|---|
| **Фонарь** | Без него ничего не найти. Но существо видит свет с 3000 единиц вместо 450. Батарея садится за ~2 минуты. |
| **Страх** | В темноте растёт. Выше 70% игрок непроизвольно ахает — это шум. На 100% происходит срыв: крик слышно на всю карту. |
| **Существо** | Патрулирует, идёт на шум, гонится по прямой видимости, обыскивает район, где потеряло игрока. |

Отсюда центральная дилемма: выключить фонарь безопасно от существа, но страх загонит
тебя в срыв. Держать фонарь включённым — тебя увидят. Играть приходится короткими
перебежками со светом и паузами в темноте, ровно до того момента, пока хватает нервов.

**Цель:** собрать все фрагменты, разбросанные по уровню, и открыть выход.

---

## Быстрый старт

1. Установи **Unreal Engine 5.4** (или новее — редактор предложит сконвертировать проект).
2. Правый клик по `Felar.uproject` → **Generate Visual Studio project files**
   (на Linux/Mac — `GenerateProjectFiles.sh`).
3. Собери проект в IDE конфигурацией **Development Editor**, либо просто открой
   `Felar.uproject` — редактор предложит скомпилировать модуль сам.
4. Дальше нужно собрать уровень — см. следующий раздел.

> Уровня (`.umap`), Blueprint'ов и виджетов в репозитории нет: это бинарные ассеты
> Unreal, их нельзя хранить как текст. Всё, что ниже, делается один раз руками
> и занимает минут двадцать.

## Сборка уровня в редакторе

### 1. Карта

- **File → New Level → Basic**. Сохрани как `Content/Maps/L_House`.
- **Project Settings → Maps & Modes**: `Editor Startup Map` и `Game Default Map` → `L_House`.
- Построй коробку из BSP или кубов: несколько комнат, коридоры, двери. Точность неважна —
  важна планировка: тупики, петли и развилки. Прямой коридор без ответвлений убивает всю игру.
- Убери или сильно приглуши направленный свет и скайлайт. Должно быть **темно**.

### 2. Навигация (без неё существо не сдвинется с места)

- Добавь **NavMeshBoundsVolume**, растяни на всю играбельную зону.
- Нажми `P` — зелёная заливка показывает, где существо может ходить. Если её нет,
  проверь, что пол — статичная геометрия, а объём накрывает уровень.

### 3. Blueprint'ы от C++ классов

В **Content Browser → Add → Blueprint Class → All Classes** создай наследников:

| Родитель (C++) | Blueprint | Что настроить |
|---|---|---|
| `FelarCharacter` | `BP_Player` | Меш рук (опционально), проверь позицию камеры |
| `StalkerCharacter` | `BP_Stalker` | Скелетный меш + Anim Blueprint, звуки в `OnStateChangedBP` |
| `FelarGameMode` | `BP_GameMode` | Default Pawn → `BP_Player` |
| `FelarPlayerController` | `BP_PlayerController` | `HUDWidgetClass` → твой виджет |
| `FragmentPickup` | `BP_Fragment` | Static Mesh, звук подбора |
| `BatteryPickup` | `BP_Battery` | Static Mesh, `ChargeAmount` |
| `HidingSpot` | `BP_Wardrobe` | Меш шкафа, положение `HidePoint` и `ExitPoint` |
| `ExitDoor` | `BP_ExitDoor` | Меш двери, анимация в `OnDoorOpenedBP` |
| `SafeLightZone` | `BP_LightZone` | Размер `Volume` |

В `BP_GameMode` укажи `PlayerControllerClass` → `BP_PlayerController`.
В **World Settings** карты выстави `GameMode Override` → `BP_GameMode`.

> **Важно про `HidingSpot`:** `ExitPoint` обязан быть **снаружи** меша шкафа.
> Если он внутри, игрок при выходе застрянет в геометрии.

### 4. Расстановка

- **6 штук `BP_Fragment`** по дальним углам карты. Количество нужных фрагментов
  считается автоматически по числу расставленных — менять ничего не надо.
- **3–4 `BP_Battery`** по маршруту между фрагментами.
- **3–5 `BP_Wardrobe`** — обязательно рядом с местами, где существо ходит часто.
- **2–3 `BP_LightZone`** + настоящая лампа рядом с каждой. Скупо: чем их больше,
  тем слабее давит темнота.
- **1 `BP_ExitDoor`** у выхода.
- **1 `BP_Stalker`** подальше от точки старта игрока.
- **Точки патрулирования:** расставь пустых актёров (`Empty Actor`) по уровню и добавь
  каждому тег `PatrolPoint` (Details → Actor → Tags). Если точек нет, существо будет
  бродить случайно — работает, но маршрут получается менее осмысленным.

### 5. HUD

Создай **Widget Blueprint** и подпишись в нём на события (все они `BlueprintAssignable`):

- `UFlashlightComponent::OnBatteryChanged` → полоска заряда
- `UFearComponent::OnFearChanged` → виньетка / пост-процесс
- `UFearComponent::OnPanicStateChanged` → сердцебиение
- `UInteractionComponent::OnFocusedActorChanged` → подсказка в центре экрана
- `AFelarGameState::OnFragmentsChanged` → счётчик «3 / 6»
- `AFelarGameState::OnGameFinished` → экран конца

Укажи класс виджета в `BP_PlayerController → HUDWidgetClass`.

### Почему сделано именно так

**Компоненты, а не один жирный класс персонажа.** Фонарь, страх и взаимодействие —
три независимых `ActorComponent`. Каждый можно тестировать, отключать и вешать на
другого актора отдельно. `FelarCharacter` только связывает их и переводит ввод в события.

**Интерфейс вместо Cast.** `IFelarInteractable` даёт игроку работать с дверью, шкафом и
запиской одинаково, без `Cast To BP_Door` на каждый тип. Каждый `Cast` в Blueprint тянет
весь целевой класс со всеми его ассетами в память при загрузке — на большом проекте это
превращается в минуты загрузки.

**Делегаты вместо прямых ссылок.** Компоненты не знают ни про UI, ни друг про друга:
они рассылают события, а подписчики сами решают, что с ними делать. Поэтому
`FearComponent` понятия не имеет о существовании существа — шум из его событий делает
`FelarCharacter`.

**Конечный автомат на C++ вместо Behavior Tree.** BT и Blackboard — бинарные ассеты:
их нельзя положить в git как текст, нельзя нормально отревьюить в диффе и нельзя
смержить, если двое правили один файл. Для четырёх состояний автомат в коде короче
и полностью читаем.

**Классический ввод вместо Enhanced Input.** Enhanced Input требует Input Action —
это тоже ассеты. `Config/DefaultInput.ini` — текстовый файл, поэтому проект собирается
и играется без единого ручного шага в редакторе. Когда проект обрастёт ассетами,
переход на Enhanced Input займёт полчаса.

**Дозированный Tick.** Трассировка взаимодействия — раз в 0.1 с, проверка видимости
существа — раз в 0.25 с, перестроение пути в погоне — раз в 0.35 с, радиус зрения
пересчитывается только при смене состояния фонаря. Разницы в поведении не видно,
а нагрузка падает в разы. Фонарь и шкаф вообще тикают только когда работают.

## Настройка баланса

Все числа вынесены в `EditDefaultsOnly` — правятся в Blueprint'ах без перекомпиляции C++.

| Что | Где | По умолчанию |
|---|---|---|
| Время работы фонаря | `FlashlightComponent → DrainPerSecond` | 0.8 (~2 мин) |
| Скорость роста страха | `FearComponent → DarknessFearPerSecond` | 4.5 |
| Порог паники | `FearComponent → PanicThreshold` | 70 |
| Зрение в темноте | `StalkerCharacter → SightRadiusDark` | 450 |
| Зрение на свету | `StalkerCharacter → SightRadiusLit` | 3000 |
| Слух | `StalkerCharacter → HearingRange` | 2200 |
| Скорость погони | `StalkerCharacter → ChaseSpeed` | 560 |

Скорость погони (560) намеренно ниже скорости бега игрока (600): от существа **можно**
убежать, но запаса хватает секунд на десять, пока не кончится выносливость.
Если сделать существо быстрее игрока, погоня превратится в гарантированную смерть,
и игрок перестанет рисковать вообще.

## Что дальше

Порядок, в котором стоит наращивать игру:

1. **Собрать уровень и пройти его.** Всё остальное бессмысленно, пока не понятно,
   как ощущается базовая петля.
2. **Звук.** В хорроре он даёт больше половины эффекта: шаги, дыхание, скрип,
   рычание существа в `OnStateChangedBP`. Это следующий по важности шаг после уровня.
3. **Пост-процесс страха.** Виньетка, зерно, тремор камеры от `OnFearChanged`.
4. **Записки и лор.** Наследник `PickupActor`, показывающий текст.
5. **Второе существо или второй этаж** — только когда первое работает хорошо.
